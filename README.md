## 1. 项目简介

操作者戴上一只装有 **ICM20689 六轴惯性传感器** 的棉质手套，通过手腕的**倾斜与扭转**控制小车运动与云台朝向：

- 手腕**前倾/后仰** → 小车前进/后退
- 手腕**左倾/右倾** → 小车左右平移
- 手腕**水平扭转** → 二自由度云台水平转动
- 前倾角度同时可映射为**云台俯仰**（云台模式）

手套端用 **ESP32** 做姿态解算与手势映射，结果通过 **nRF24L01+ 2.4G 射频**发给定位于车体的 **树莓派**；树莓派驱动全向轮底盘与舵机云台，并把 CSI 广角摄像头的 RTSP 视频流回传。

### 1.1 为什么要做这个项目

| 维度 | 说明 |
| --- | --- |
| **技术性** | 覆盖 IMU 采样 → 姿态融合（Mahony）→ 非线性映射 → 低延迟无线 → 电机/舵机执行的完整链路，是物联网"感知—传输—控制"三层架构的最小闭环 |
| **实用性** | 免手持设备的遥控方式，适合救援机器人、教学演示、无障碍操作等场景 |
| **可量化** | 姿态精度、端到端时延、丢包率都有明确指标（见 [技术指标](#62-关键技术指标)），便于结题验收 |
| **可扩展** | 手势识别、ESP-NOW、WiFi 图传、9 轴融合都有清晰的演进路径（见 [路线图](#8-路线图)） |

### 1.2 系统架构

```
┌──────────────────────────── 手套采集端（已完成） ───────────────────────────┐
│                                                                            │
│   ICM20689 ──I2C──► ESP32 ──SPI──► nRF24L01+ ──┐                            │
│   (六轴原始)      │  Mahony 姿态解算           │  2.4G / 250kbps            │
│                   │  死区→非线性→限幅          │  信道 76 / 地址 GLV01       │
│                   │  14 字节定长包 + CRC-8     │  50Hz 单向发送              │
│                   └───────────────────────────┘                            │
└─────────────────────────────────────┬──────────────────────────────────────┘
                                      │  无电气连接，纯无线
┌─────────────────────────────────────▼── 机器人端（接口已定义，固件待实现）──┐
│                                                                            │
│   nRF24L01+ ──SPI──► 树莓派 4B ──┬──► TB6612 ──► 3× 全向轮电机             │
│                     (解包/校验)   ├──► PCA9685 ─► 2× 舵机云台               │
│                                  └──► CSI 广角摄像头 ──► RTSP 视频流         │
└────────────────────────────────────────────────────────────────────────────┘
```

**设计要点**：手套端与车体**没有任何电气连接**，只有一条 2.4G 无线链路。这既是"免束缚"体验的来源，也意味着通信可靠性必须由应用层协议保证（CRC + 超时停车）。

## 4. 快速开始

### 4.0 你需要准备的

**硬件**（完整清单见 [hardware_list.md](docs/hardware_list.md)）：
ESP32 DevKit V1 ×1、**ICM20689 模块 ×1（必须带 I2C 引出）**、nRF24L01+ 模块 ×1、100µF 电解电容 ×1、棉质手套 ×1、面包板与杜邦线。

**软件**：
- [Arduino IDE](https://www.arduino.cc/en/software) 2.x
- ESP32 开发板包（工具 → 开发板 → 开发板管理器 → 搜索 `esp32` 安装）
- **RF24** 库（工具 → 管理库 → 搜索 `RF24` → 选作者 **TMRh20** 的版本安装）

> ICM20689 不需要任何库 —— 固件直接操作寄存器。

### 4.1 接线

照着 [wiring_diagram.md](docs/wiring_diagram.md) 的表格接。三句话版本：

| 引脚 | → ESP32 | | nRF24L01 | → ESP32 |
| --- | --- | --- | --- | --- |
| VCC | 3V3 | | VCC | 3V3（⚠️ 不是 5V） |
| GND | GND | | GND | GND |
| SCL/SCLK | GPIO22 | | CE | GPIO4 |
| SDA/MOSI | GPIO21 | | CSN | GPIO5 |
| SDO/AD0 | GND（地址 0x68） | | SCK / MOSI / MISO | GPIO18 / 23 / 19 |
| **CS** | **3V3（必须拉高）** | | | |

> ⚠️ ICM20689 的 **CS 必须接 3V3**：芯片用 CS 电平判断走 SPI 还是 I2C，CS 悬空会导致 I2C 完全无应答，现象和"模块坏了"一模一样。

**外加一步，别省**：在 nRF24L01 的 VCC 与 GND 之间焊一个 **100µF 电解电容**（长脚接 VCC），引脚尽量短。
这一步能解决约 60% 的"发几包就复位"问题。

### 4.2 打开并上传

Arduino IDE 要求**文件夹名 == 主文件名**。所以：

1. 新建一个名为 `IMU_Car` 的文件夹
2. 把 `code/arduino/IMU_Car.ino` 复制进去，得到 `IMU_Car/IMU_Car.ino`
3. 用 Arduino IDE 打开它
4. 选择开发板 **ESP32 Dev Module**、选择正确端口
5. 点上传

> 上传失败提示 `Connecting...` 时按住板上的 **BOOT** 键不放，看到开始写入再松开。

### 4.3 上电与标定

**这一步决定了能不能用**：

1. 把手套**平放**在桌面上（手心朝下，模块朝上）
2. **保持完全静止**，再插 USB 上电
3. 等待约 3 秒，期间 LED 常亮
4. 看到串口打印 `RUN  frame=20ms` 说明标定完成

正确的开机会是这样：

```
=========================================
 IMU Gesture Car - Glove TX  v1.0.0
=========================================
OK   ICM20689 ready (id=0x98, gyro +-500dps, accel +-4g)
CAL  keep the glove STILL and LEVEL for ~2s ...
CAL  gyro_bias(dps) = +0.31 -1.24 +0.87  (n=1000)
CAL  level_ref = roll +0.42  pitch -0.18
OK   nRF24L01 ready (ch=76, 250kbps, addr=GLV01)
RUN  frame=20ms  mode=DRIVE
PKT  sizeof=14  head=0xA5
```

> 没有 nRF24L01 也能跑：会打印 `ERR nRF24L01 init failed` 并进入 **BENCH 模式**，姿态数据照常输出，可以先把传感器部分调好。

### 4.4 验证姿态

打开串口监视器（**波特率 115200**），倾斜手套，观察输出：

```
[  130] roll=   2.10 pitch=  11.85 | vx=  20 vy=   0 pan=   0 tilt=   0 | DRIVE  ARMED tx=OK   imu=OK
```

| 期望现象 | 说明 |
| --- | --- |
| 平放时 `roll≈0`、`pitch≈0` | 水平基准正确 |
| 手指下压 → `pitch` 变正、`vx` 变正 | 前后方向正确 |
| 手腕右倾 → `roll` 变正、`vy` 变正 | 左右方向正确 |
| 倾斜 10° 左右时 `vx` 约 10 | 映射曲线符合设计 |

**方向反了怎么办**：不要改算法，改文件开头的符号宏即可：

```cpp
#define VX_INVERT  (-1)   // 前后反了
#define VY_INVERT  (-1)   // 左右反了
```

### 4.5 操作说明

| 操作 | 效果 |
| --- | --- |
| 手心朝下平放 | 停车（进入死区） |
| 前倾 10°~30° | 前进，角度越大越快 |
| 左/右倾 | 左右平移 |
| 短按 **BOOT** 键 | 切换 **DRIVE（行进）/ GIMBAL（云台）** 模式 |
| 长按 **BOOT** 键 1.5 秒 | 重新取水平基准（换人佩戴时用） |
| 手超过 30° | 输出饱和在 100，不会失控 |

## 5. 通信协议速览

手套端每 20ms 发一个 **14 字节**定长包，完整定义见 [分层说明 §9.2](docs/IMU人体姿态控制小车%20分层说明及具体实施步骤.md)。

| 偏移 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0 | `head` | u8 | 固定 `0xA5` |
| 1 | `seq` | u8 | 帧序号，算丢包率 |
| 2 | `flags` | u8 | bit0 手势有效 / bit1 云台模式 / bit2 IMU正常 / bit3 标定中 / bit4 上帧发送失败 |
| 3 | `vx` | i8 | 前后 -100~100 |
| 4 | `vy` | i8 | 左右 -100~100 |
| 5 | `tilt` | i8 | 云台俯仰 -100~100 |
| 6-7 | `panDelta` | i16 | 云台水平**增量**，单位 0.1° |
| 8-9 | `roll10` | i16 | 相对水平基准的 roll，0.1° |
| 10-11 | `pitch10` | i16 | 相对水平基准的 pitch，0.1° |
| 12 | `dtMs` | u8 | 本帧周期，查帧率 |
| 13 | `crc` | u8 | 前 13 字节的 CRC-8（poly 0x07） |

**射频参数（两端必须一致）**：信道 `76`、速率 `250kbps`、地址 `GLV01`、CRC `16bit`、负载 `14` 字节、关闭自动应答。

> **车端最低安全要求**：200ms（10 帧）收不到合法包 → 必须主动停车。不能只依赖 `flags` 位。

## 6. 技术指标

### 6.1 设计目标

| 指标 | 目标值 | 当前状态 |
| --- | --- | --- |
| 姿态静态精度 | ±0.5° | 待实测 |
| 姿态动态误差 | < 2° | 待实测 |
| 控制帧率 | 50Hz（抖动 < ±2ms） | 待实测 |
| 端到端时延 | < 60ms | 待实测 |
| 无线丢包率（同房间） | < 1% | 待实测 |
| 有效控制距离 | ≥ 10m | 待实测 |
| 续航（5000mAh 充电宝） | > 8h | 待实测 |

> 实测数据会补充到 [分层说明 §10.3](docs/IMU人体姿态控制小车%20分层说明及具体实施步骤.md) 的联调记录表。**这些数字是结题报告里最有说服力的部分，一定要测。**

### 6.2 关键技术点

| 技术点 | 做法 | 为什么 |
| --- | --- | --- |
| 姿态融合 | Mahony AHRS（PI 互补滤波） | 比 Kalman 简单、参数少、在 ESP32 上单帧 < 0.2ms |
| 传感器驱动 | ICM20689 直接读寄存器（不依赖 IMU 库），`WHO_AM_I` + **三重回读校验** | 能确认"型号对不对、配置写没写进去"；硬件问题在初始化阶段就暴露 |
| 陀螺零偏 | 上电静态采样 1000 点取均值 | 消除 ±20°/s 的固件零偏，不打掉就完全没法用 |
| 信号滤波 | **只滤加速度（4 点滑动平均），不滤陀螺** | 陀螺滤波 = 相位滞后 = 手感变肉 |
| 手势映射 | 死区 → 归一化 → 幂函数非线性 → 限幅 | `s^1.6` 一个参数就能调"软硬"，比分段线性少 5 个参数 |
| yaw 漂移 | **不用 yaw 做控制**，云台水平改用陀螺角速度积分成增量 | 6 轴 IMU 的 yaw 必然漂移，用绝对角会越来越偏 |
| 低延迟 | 关闭 nRF 自动应答/重发，丢帧不补发 | 重发 3 次 = 750ms，比丢一帧（20ms）糟糕得多 |
| 协议健壮性 | `#pragma pack(1)` + `static_assert(sizeof==14)` + CRC-8 + 帧头 + 序号 | 跨平台结构体对齐是最隐蔽的坑；断言让"改坏了"在编译期就暴露 |
| 调试友好 | 三级调试输出 + CSV 模式 + BENCH 降级模式 + LED 状态灯 | 没有车、没有射频也能验证大部分逻辑 |

## 7. 常见问题

| 现象 | 最可能的原因 | 去这里查 |
| --- | --- | --- |
| 串口没输出 | USB 线只能充电 / 端口选错 | [debug_faq §2.1](docs/debug_faq.md) |
| `ERR ICM20689 init failed` | 没供电 / SDA-SCL 接反 / **CS 没拉高** / AD0 悬空；看打印的 `WHO_AM_I` 值 | [debug_faq §3.1](docs/debug_faq.md) |
| 姿态一直漂 | 零偏没标定好 / 手抖了 | [debug_faq §4.1](docs/debug_faq.md) |
| 方向相反 | `IMU_MOUNT` 或 `*_INVERT` 选错 | [debug_faq §4.4](docs/debug_faq.md) |
| `ERR nRF24L01 init failed` | 没 100µF 电容 / 接了 5V | [debug_faq §5.1](docs/debug_faq.md) |
| 发几包就复位 | nRF 发射瞬间掉压 | [debug_faq §5.4](docs/debug_faq.md) |
| 车能动但很迟钝 | 死区/满量程/gamma 参数 | [debug_faq §6.2](docs/debug_faq.md) |
| 车端收不到包 | 两端信道/地址/速率不一致 | [debug_faq §8.1](docs/debug_faq.md) |

**通用第一招**：把 `DEBUG_LEVEL` 改成 **2**（每帧输出），先看清数据，再猜原因。
