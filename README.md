## 总括

**本项目当前是「IMU 阈值判断 + 硬编码映射 + 人工遥控」的规则化遥操作系统；本项目的升级方向是「端侧智能支撑下的意图级共享自治」——以专家示教数据和操作员历史数据为先验，端侧模型实时解析当前动作意图，在不剥夺操作员控制权的前提下修正、约束并补全指令，从而提升人机协同的一致性、精度与容错能力。**

先把三件事说清楚，避免误读：

1. **AI 不是另起一条赛道，而是补上「意图」这一层。** 本仓库已完成的固件（`code/arduino/IMU_Car/IMU_Car.ino`，约 790 行，编译零告警）是一条确定性链路：六轴姿态 → 死区 → 幂函数 → 限幅 → 14 字节包。它能「跟着手走」，但不理解「我想干什么」；换一个人、换一次佩戴，就得重新调参。
2. **边缘智能是支撑性技术，不是亮点本身。** 它只让「采集 → 判定」这一段在端侧变得可行、够快、够省、够安全，解决**实时性、带宽、功耗、信息安全**四项硬约束。同一套模型放云端不会更聪明，只会更慢、更贵、更不安全。**真正的创新在映射算法与共享自治机制。**
3. **人在回路是红线，不是可选项。** AI 只能在 **L1 修正 / L2 约束 / L3 建议 / L4 委托** 四级权限内动作，任何时刻操作员的一键接管优先，AI 不得覆盖停车权。

## 1. 项目背景与定位

### 1.1 需求从哪来

无人化正在重写战场：俄乌冲突中约 **80% 的人员伤亡来自无人机袭击**而非炮火直伤 [1]；城镇楼宇争夺中，内部结构复杂、视野受限，直接突入的代价极高（马里乌波尔围城战持续近两个月 [2]）。装备自由度越高，传统摇杆/手柄的操控难度越是指数上升——设备体积质量大、操作复杂，既影响机动性，又放大了复杂操作下的误操作概率 [3]。

肢体动作是最符合人类直觉的交互通道。本项目的设想是：**用穿戴式设备捕捉操作员的自然动作，驱动一台孪生机器人完成机动与侦察**。军事上可缩短培训周期、降低巷战伤亡；民用上可延伸到农业、文旅、应急救援等场景。

### 1.2 定位：AI 只补「意图」这一层

| 层次 | AI 是否介入 | 理由 |
| --- | --- | --- |
| 姿态解算（Mahony） | 否 | 确定性算法已足够，误差 < 2°，换成学习模型只会更难解释、更难验收 |
| **手势识别与个体自校准** | **是（落点 ①）** | 个体差异、佩戴差异、冗余动作无法用常数覆盖，必须由数据驱动 |
| **动作—指令映射** | **是（落点 ②）** | 手工 gamma/死区只能表达「推多少走多少」，表达不了意图；改由示教学习 |
| **机器人端环境感知** | **是（落点 ③）** | 二维画面没有距离与语义，操作员在窄通道、低照度下只能靠猜 |
| 运动执行（运动学 / PID / 舵机） | 否 | 经典控制已达标，替换无收益 |
| 安全仲裁与权限 | 否（规则 + 门限） | 必须可解释、可审计、可一键接管，不能是黑箱 |

> **边缘智能的边界**：它是上述三个落点的**部署形态与使能条件**，负责把模型压缩到能跑、把延迟压到够低、把原始数据留在端侧。它本身不产生智能增量——这一点在结题报告里必须写清楚，否则「边缘智能」会被误读成创新点。


## 2. 拟解决的问题

> 五个问题不是并列的「工作内容」，而是**五条必须给出可测判据的技术矛盾**。每条都写清：现状（B0）是什么、为什么不够、要做到什么、拿什么判据验收。

### 2.1 问题一：一人一套参数——个体差异与动作漂移

**现状（B0）**：每次上电静止 2s 采 1000 点求陀螺零偏，平放 0.5s 取水平基准，之后整条链路的死区（4°）、满量程（30°）、gamma（1.6）、云台角速度死区（8°/s）全是**编译期常数**。换人、换手套、模块松动、久戴温漂，都要长按 BOOT 重新取基准，再由人眼判断「手感对不对」。

**为什么不够**：常数是「平均人」的参数。实际操作中，有人手腕活动范围只有 ±15°，有人到 ±35°；有人静止时手抖 ±2°，有人 ±5°。为了保证不误动，只能把死区放大——代价是小角度微调彻底失效。这就是「能用但不好用」的根源。

**要做到（B1）**：把标定从「人工判读 + 重取基准」变成**自动、个体化、可拒识**的三件事——① 每次佩戴 3s 内自动完成零偏 + 水平 + 佩戴方向判定；② 用不超过 30s 的个人数据在端侧更新个体模型（原型/最后层适配，原始数据不出端）；③ 对分布外输入（新动作、传感器松动、佩戴反转）显式拒识并提示重标定，而不是输出一个看起来合理的错误指令。

**判据**：首次佩戴到可用 ≤ 3s；6 人 × 3 次跨会话开箱可用率 ≥ 90%；同指令跨人输出离散度（CV）下降 ≥ 40%。

### 2.2 问题二：阈值只能表达「推」，表达不了「意图」

**现状（B0）**：映射是 `mapAxis(pitchRel, 4°, 30°, ±1)` 这类三段式曲线——一个连续的比例关系。它能表达「前倾 20° ≈ 速度 60%」，但不能表达「挥手 = 确认」「画圈 = 召回」「捏合 = 微调」「快速回中 = 急停」这些**离散意图**，也无法区分「有意的持续前倾」和「无意识的抬手」。

**为什么不够**：操作员要完成的是**任务**（进房间、跟瞄目标、退回安全区），不是持续输出一个电压。全靠连续量表达任务，等于把任务分解的负担全部压在人身上；而换人即失效的曲线参数，让「降低培训成本」这个立项初衷打了折扣。目前的调参靠经验试凑，一次完整调参约需 1–2 人·天，且不可迁移。

**要做到（B1）**：在连续控制之上加一层**意图解释**——双头模型同时输出「连续控制量（vx/vy/pan/tilt）+ 离散意图标签 + 置信度」。映射参数由专家示教学习而来，但**输出必须经过安全包络硬限幅**（最大速度、最大加速度、工作空间），保证学习模型不能突破可解释的下界。同时保留全手工基线，作为消融对照。

**判据**：8 类手势 + 1 类拒识，受试者内准确率 ≥ 95%、跨人 ≥ 88%；意图映射输出与专家金标准一致率 ≥ 90%；调参工时从人·天级降到 ≤ 2 人·小时。

### 2.3 问题三：机器人端「看不见」，判断全压给操作员

**现状（B0）**：车端只有一路 CSI 广角 + RTSP 二维画面。没有距离、没有深度、没有目标语义。唯一的主动安全机制是 **200ms 收不到合法包就停车**——这是通信层的兜底，不是感知层的避障。

**为什么不够**：共享自治的前提是机器人知道「前面 0.3m 有堵墙」。纯遥操作把这个判断全部外包给操作员的视觉与经验：窄门、台阶、低照度、遮挡场景下，碰撞与路径偏离是必然结果，而不是操作失误。二维画面还会放大「看起来能过、实际过不去」的误判。

**要做到（B1）**：车端建立**三层轻量感知**——① 关键帧目标检测（人 / 门 / 桌椅 / 箱体，≥ 6 FPS）；② 用检测框底边 + 地面平面单应做**快速测距**（≤ 10ms/帧，25Hz 可用）；③ 低频单目深度（2–5 FPS）用于建立局部代价地图；由此得到最小障碍距离 `d_min` 与方位，作为**「约束」级权限（L2）的输入**。关键设计：**视觉只否决、不改向**——它可以让前进分量衰减，但不能替操作员转向。

**判据**：自建 2000 帧数据集上 mAP@0.5 ≥ 0.6；1.5m 内 `d_min` 相对误差 ≤ 15%；同赛道碰撞次数下降 ≥ 50%；最小安全距离（0.3m）保持率 ≥ 95%。

### 2.4 问题四：AI 一旦介入，误判比人操作慢更危险

**现状（B0）**：没有 AI，所以「安全」等价于「操作员的技术 + 超时停车」。一旦引入 AI 直接修改指令，风险结构完全改变：**AI 误判造成的后果，比人慢半拍严重得多**——慢半拍只是手感差，误判一次可能是撞墙、撞人、掉楼梯。

**为什么不够**：只写「加入辅助决策」而不定义权限边界，等于把安全责任推给一个无法追责的模型。评审会问三个问题，现在都答不上来：AI 什么时候能改指令？改多少？出事怎么复现？

**要做到（B1）**：把「辅助」拆成**四级可配置权限 + 置信度门限 + 一键接管 + 失效降级 + 可审计日志**。硬性约束三条：① AI 的任何输出都不能覆盖操作员的停车与接管指令；② 所有 AI 修正必须能按帧回放（输入摘要、输出、权限等级、门限、是否被接管）；③ 模型超时（> 100ms）或输入分布外，自动降级到 L1（修正），绝不「沉默地继续用旧值」。

**判据**：一键接管时延 ≤ 200ms；无操作员意图时 AI 主动动作的误触发率 ≤ 1%/h；由 AI 引发的危险动作次数 **0**；L1–L4 权限切换成功率 100%。



### 2.6 四项硬约束：为什么必须端侧

| 约束 | 量化要求 | 端侧如何满足 | 放云端会怎样 |
| --- | --- | --- | --- |
| 实时性 | 端到端 **P95 ≤ 100ms**（含推理） | 推理 15ms + 本地链路 2ms，控制回路 50Hz 不被阻塞 | 4G/WiFi 往返 50–150ms，抖动不可控，丢包即失控 |
| 带宽 | 见下表分解 | 只上传判定结果与事件，不上传原始流 | 多节点/含深度时上行链路直接打满 |
| 功耗 | 手套 ≥ 8h，车端视觉开启 ≥ 3h | 端侧模型 ≤ 300KB，只在关键帧唤醒 | 射频常开 + 重传，续航腰斩 |
| 信息安全 | 原始动作数据不出端 | 个人历史只存端侧，可一键清除；示教数据脱敏后再入库 | 操作员生物行为特征暴露在链路上，可被指纹识别 |

**「带宽降 2–3 个数量级」的严格分解**（不做夸大，说清前提）：

| 场景 | 原始流 | 端侧结果 | 降幅 |
| --- | --- | --- | --- |
| 单只手套 IMU（6 轴 16bit @200Hz） | 2.4 kB/s ≈ 19.2 kbps | 14 B × 50Hz = 0.7 kB/s ≈ 5.6 kbps | **≈ 3.4×** |
| 12 个 IMU 节点同时上传 | ≈ 230 kbps | 汇聚结果 5.6 kbps | **≈ 41×** |
| 含原始深度图（640×480×2B @10FPS） | ≈ 49 Mbps | 事件 + 检测框 ≈ 16 kbps | **≈ 3000×（3 个数量级）** |



### 2.7 五个核心指标的定义与口径

指标不定义清楚，「提升 30%」就是空话。以下口径同时写入测试脚本（`ai/eval/`）与结题报告。

| 指标 | 操作化定义 | 采集方式 |
| --- | --- | --- |
| **指令准确率** | 系统输出与「专家标注金标准」的一致率。连续量按容差带判定（\|Δ\| ≤ 满量程 10% 记为一致），离散量按标签一致 | 每任务 30 条轨迹 × 4 任务，双人独立标注，分歧由第三人裁定 |
| **响应一致性** | ① 受试者内：同一指令重复 10 次的输出变异系数 CV；② 跨人：不同操作员完成同一任务的指令序列 DTW 归一化距离 | 标准化指令提示音触发，自动记录 |
| **任务完成时间** | 标准赛道（S 形 → 窄门 → 目标对位 → 返回）从起点到终点，含 3 次目标确认，超时 180s 记失败 | 秒表 + 视觉标记双记录 |
| **碰撞次数** | 车体与障碍发生 ≥ 0.1s 接触即计 1 次；同赛道连测 10 次取均值 | 接触开关 + 视频复核 |
| **路径偏离度** | 实测轨迹与期望轨迹的 RMS 偏差，按赛道长度归一化 | 顶视相机 + AprilTag 定位，或轮式里程计 + 视觉校正 |

另设两个**安全指标**（不计入「性能提升」，只做红线）：一键接管时延、AI 引发的危险动作次数。

## 3. 技术路线

> **编号说明**：本节 **L0–L3** 指能力推进阶段（手势识别 / 视觉感知 / 意图映射 / 数字孪生）；§3.4 中的 **L1–L4** 指共享自治的权限等级（修正 / 约束 / 建议 / 委托）。两套编号含义不同，按上下文区分。

### 3.1 总体架构

```
        ┌────────────── ① L0 端侧手势识别（手套 · ESP32 → 可选 ESP32-S3）──────────────┐
        │ ICM20689 200Hz → 零偏/水平/佩戴自校准 → 双头轻量模型（回归 + 分类）→ OOD 拒识   │
        │ 输出：vx vy panΔ tiltΔ + intent_id + conf      预算：≤15ms/帧 · 模型 ≤300KB int8 │
        └───────────────────────────────────┬───────────────────────────────────────────┘
                        2.4G 双向（下行指令 50Hz / 上行状态 20Hz）或 ESP-NOW
        ┌───────────────────────────────────▼── ② L1 视觉感知（车端 · 树莓派 4B）────────┐
        │ CSI 广角 → 检测（≥6FPS 关键帧）＋ 地面单应快速测距（≤10ms）＋ 低频深度（2–5FPS）  │
        │ → 局部代价地图 → d_min / 方位 → 避障 veto（只否决不改向）                        │
        │ 执行：3× 全向轮运动学 · 云台 PID · RTSP 推流                                     │
        └───────────────────────────────────┬───────────────────────────────────────────┘
        ┌───────────────────────────────────▼── ③ L2 意图映射与共享自治 ─────────────────┐
        │ 示教/个人/公开数据 → 行为克隆 + 个体适配 → 安全包络硬限幅 → L1~L4 仲裁 + 门限     │
        └───────────────────────────────────┬───────────────────────────────────────────┘
        ┌───────────────────────────────────▼── ④ L3 数字孪生（MuJoCo · PC）─────────────┐
        │ 手套-底盘-云台-场景 → 域随机化预训练 → 系统辨识 → sim2real 参数回流 → 回归门禁    │
        └───────────────────────────────────────────────────────────────────────────────────┘
```

**四层之间的关系**：① 决定「人想干什么」，② 决定「环境允许干什么」，③ 在两者冲突时决定「谁说了算、听多少」，④ 让前三层可以在不撞墙的前提下反复试错。缺任何一层，系统都退化回 B0 的规则化遥控。

### 3.2 阶段 L0：端侧手势识别与个性化自校准

| 项 | 内容 |
| --- | --- |
| **输入** | ICM20689 六轴 200Hz（accel ±4g / gyro ±500dps）；Mahony 输出的 roll/pitch 与 gz；佩戴状态标志 |
| **方法** | ① **滑窗特征**：1.0s 窗、0.1s 步长（50% 重叠），时域统计 + 频域能量 + 重力投影 + 角速度积分，共 ≈ 120 维；② **双头轻量模型**：共享 1D-CNN + GRU 编码器（≈ 5 万参数），连续头回归 `vx/vy/panΔ/tiltΔ`，离散头输出 9 类（8 手势 + 拒识）；③ **自校准**：零偏（2s 静态）+ 水平基准（0.5s 平放）+ 佩戴方向自动判定（重力方向 × 主运动轴），共 ≤ 3s；④ **个体适配**：端侧只做推理 + 原型均值/最后层更新（≤ 30s 个人数据，不训练整个网络）；⑤ **OOD 拒识**：用重构误差与输出熵联合判定，超阈值输出「拒识 + 提示重标定」 |
| **输出** | `ControlPacket v2`：14 字节旧包（向后兼容）+ 4 字节扩展（intent_id / conf / 模型版本 / 端侧推理耗时） |
| **资源预算** | int8 模型 ≤ 300KB（上限 2MB 作为工程余量）；峰值 RAM ≤ 2MB；单帧推理 ≤ 15ms @ 240MHz |
| **为什么这样设计** | 训练在 PC/服务器完成，**端侧只做推理与轻量适配**——这是「边缘智能」而不是「边缘训练」，避免在 MCU 上做梯度下降这种不可控的事；短窗 + 轻模型是为了守住 15ms，窗长再大 50Hz 控制回路就断了 |
| **验收判据** | 受试者内 ≥ 95%，跨人（留一受试者）≥ 88%；拒识类误接收 ≤ 2%；推理 ≤ 15ms；模型 ≤ 300KB |

### 3.3 阶段 L1：机器人端视觉感知与局部自主

| 项 | 内容 |
| --- | --- |
| **输入** | CSI 广角视频流（1280×720 → 320×320 降采样）；云台角度；轮式里程计 |
| **方法** | ① **检测**：YOLOv8n / NanoDet int8，关键帧 6–10 FPS，类别 = 人 / 门 / 桌椅 / 箱体；帧间用轻量跟踪插值补到 25Hz；② **快速测距**：标定相机俯仰与安装高度，用检测框底边 + 地面平面单应反算距离，≤ 10ms/帧；③ **低频深度**：MiDaS-small / Depth-Anything-small 量化版，2–5 FPS，仅用于建局部代价地图（8×8 格，0.5m 分辨率）；④ **避障 veto**：`d_min < 0.5m` 开始按比例衰减前向分量，`d_min < 0.3m` 直接置零；**只衰减、不改向**，方向权始终留给操作员 |
| **输出** | 上行状态包：`d_min`、障碍方位（左/中/右）、检测置信度、视觉在线标志、权限等级、接管请求 |
| **资源预算** | Pi 4B CPU：检测 ≤ 150ms/帧（异步线程）、测距 ≤ 10ms、深度 ≤ 400ms；控制回路 50Hz 独立线程，不被视觉阻塞 |
| **为什么这样设计** | 单目深度在 Pi 4B 上必然慢，所以「测距用几何、深度用地形」——几何测距保实时，深度保语义；同步用检测框底边是因为轮式底盘在平地上满足地面平面假设，比端到端回归更可解释、更省算力 |
| **验收判据** | mAP@0.5 ≥ 0.6（自建 2000 帧，4 类）；1.5m 内 `d_min` 误差 ≤ 15%；≥ 6 FPS；碰撞 ↓ ≥ 50% |

### 3.4 阶段 L2：意图级映射与共享自治

**映射部分**：

| 项 | 内容 |
| --- | --- |
| **数据** | 专家示教（团队成员 + 指导教师，4 类标准任务）、操作员个人历史、公开惯性/视觉数据集（见表 §3.6） |
| **方法** | ① 表征预训练：对比学习 + 自监督重构，在公开 + 个人数据上预训练编码器；② 行为克隆：以（状态、视觉上下文、上帧指令）为输入，以专家动作为监督，回归连续控制量 + 分类意图；③ 安全包络：学习输出先过硬限幅（`\|v\| ≤ v_max`、`\|a\| ≤ a_max`、工作空间约束），再过死区，最后才下发；④ 混合兜底：B0 手工映射始终在线，作为 L2 失效时的降级通道 |
| **为什么用行为克隆而不是强化学习** | 样本效率高（示教数据可直接用）、可控（不会探索出危险动作）、可解释（能对着示教视频复盘）。RL 只作为远期备选，不写入必做 |
| **验收判据** | 意图准确率 ≥ 90%；响应一致性 CV ≤ 10%；任务完成时间 ↓ ≥ 25%；路径偏离 ↓ ≥ 30% |

**共享自治部分**（本项目的核心机制）：

| 等级 | 名称 | AI 做什么 | 操作员保留什么 | 触发条件 | 具体例子 |
| --- | --- | --- | --- | --- | --- |
| **L1** | 修正 | 平滑、去抖、个体偏差与延迟补偿 | 全部意图与幅度 | 始终生效 | 手抖 ±2° 不再产生 0.2m/s 的速度抖动 |
| **L2** | 约束 | 限速、限幅、避障否决 | 方向、启停、接管 | `d_min` 越限 或 超安全包络 | 前方 0.3m 有墙 → 前进分量归零，但不替人转向 |
| **L3** | 建议 | 给出候选动作/路径/目标框，等待确认 | 是否采纳 | 置信度中段 + 任务上下文 | 「检测到门口，建议左转 15°」，需按键确认 |
| **L4** | 委托 | 短时接管局部子任务（避障、对准、回中） | 一键接管权、停车权 | 高置信 + 操作员**显式**委托 | 窄通道内 2s 自动对中，松手立即退出 |

**门限与仲裁**：

```
置信度 conf ──┬── conf < τ1           → 仅 L1（平滑兜底），输出标记 low_conf
              ├── τ1 ≤ conf < τ2       → L2 可约束（限速/否决），不可改向
              ├── τ2 ≤ conf < τ3       → L3 生成建议，等待操作员确认
              └── conf ≥ τ3 且已委托   → L4 短时接管（≤ 3s，可被任意按键打断）
```

- **门限标定**：τ1/τ2/τ3 由验证集 ROC 曲线确定，优化目标 = 误触发率 ≤ 1%/h 且漏检率 ≤ 5%；标定结果与置信区间一并写入报告，不做「拍脑袋常数」。
- **一键接管**：BOOT 短按 = 立即接管（≤ 200ms），松手即停（deadman）；接管后 AI 降为 L1，且 **2s 内不自动升级**（防抖与防抢权）。
- **失效降级**：推理超时（> 100ms）→ L1；通信丢失 200ms → 停车；输入 OOD → 拒识 + 提示；断电 → 被动刹车。所有降级都打时间戳进日志。
- **可审计**：环形缓冲记录每帧（特征摘要、输出、权限、门限、是否被接管），支持按时间回放，用于事故复盘与答辩演示。

> **一条设计铁律**：**低置信度时宁可「不变」，也不要「猜一个」**。人慢半拍只是手感差，AI 猜错可能直接撞墙——这正是「误判比人操作慢更危险」的工程解法。

### 3.5 阶段 L3：MuJoCo 数字孪生与 sim2real

| 项 | 内容 |
| --- | --- |
| **模型** | 3× 全向轮底盘（120° 布局）+ 二自由度云台 + CSI 相机（仅运动学占位）；场景：走廊、窄门、绕障、低照度 |
| **输入注入** | 仿真端以与实物完全相同的 50Hz `ControlPacket` 注入，保证「同一份指令、两套执行体」可比 |
| **域随机化** | 摩擦系数（0.4–1.0）、底盘质量（±20%）、电机延迟（0–40ms）、丢包率（0–3%）、IMU 噪声与零偏、光源强度（视觉分支） |
| **三件用途** | ① **回归门禁**：每次改映射/仲裁，先在仿真跑 100 条轨迹，指标不劣化才允许上实物；② **参数辨识**：用实物轨迹（直线/方形/绕障）反推仿真参数，最小化轨迹残差；③ **可视化**：答辩现场演示「同一指令在孪生体与实体的同步运动」 |
| **sim2real 策略** | 系统辨识为主、残差学习为辅、实物小样本微调收尾；**不承诺**零样本迁移 |
| **验收判据** | 3 条基线轨迹 RMSE ≤ 10%；同一策略仿真/实物成功率差 ≤ 10 个百分点；回归测试覆盖率 100%（每次策略变更必跑） |

### 3.6 数据从哪来

| 类别 | 来源 | 目标规模 | 用途 | 合规要求 |
| --- | --- | --- | --- | --- |
| **专家示教** | 团队成员 + 指导教师，4 类标准任务（直线、绕障、对门、云台跟瞄） | ≥ 3 人 × 4 任务 × 30 条 = 360 条 | 行为克隆监督、映射上界、评测金标准 | 知情同意书；以编号匿名化；仅用动作与轨迹，不用影像 |
| **个人历史** | 每名受试者日常使用累积 | ≥ 6 人 × ≥ 30min | 个体适配、OOD 阈值标定 | 只存端侧；可一键清除；不上传原始数据 |
| **公开数据** | 公开惯性手势/姿态数据集（预训练与跨人泛化对比）+ 自建视觉小数据集（2000 帧、4 类、含低照度与遮挡） | 公开集全量；自建集 2000 帧标注 | 编码器预训练、跨人基线、检测训练 | 遵循原始许可；自建集随论文公开标注规范 |

### 3.7 通信协议升级与时延预算

B0 是单向 14 字节包，共享自治在物理上无法成立（车端没有回传通道）。v2 在**保持旧包不变**的前提下扩展：

| 方向 | 内容 | 频率 | 说明 |
| --- | --- | --- | --- |
| 下行（手套 → 车） | 旧 14B 包 + 4B 扩展（`intent_id` / `conf` / `model_ver` / `infer_ms`） | 50Hz | 旧包字段与 CRC 完全不变，车端可只解前 14B（向后兼容） |
| 上行（车 → 手套） | 8B 状态包（`d_min` / 方位 / 置信度 / 权限等级 / 接管请求 / 视觉在线） | 20Hz | 需要双向链路：nRF24L01+ 的 ACK payload（32B）或 ESP-NOW |

**端到端时延预算（含推理，目标 P95 ≤ 100ms）**：

| 环节 | 预算 | 实测手段 |
| --- | --- | --- |
| 采样 + Mahony 解算（20Hz 帧内） | ≤ 6ms | 固件 `micros()` 打点 |
| 端侧特征 + 推理 | ≤ 15ms | `infer_ms` 字段回传 |
| 组包 + 无线发送（250kbps，关 ACK） | < 2ms | nRF 空口时间 |
| 收包 + 仲裁 + 运动学 | < 5ms | 车端时间戳 |
| 电机 / 舵机响应 | ≤ 20ms | 视觉观察 + 编码器 |
| **合计（中位 / P95）** | **≈ 48ms / ≤ 100ms** | 端到端打点对比 |
| 视觉 veto 附加（异步，仅「约束」级生效时） | ≤ 150ms | **安全兜底**：`d_min < 0.3m` 时用最近一次估计立即限速，不等新帧 |

> 超时停车仍按旧约定：车端 200ms（10 帧）收不到合法包必须主动停车。**这是安全底线，不能只依赖 `flags` 位。**

### 3.8 三条硬创新（对比基线 + 做法 + 判据）

| # | 创新点 | 对比基线 B0 | 做法 | 可测判据 |
| --- | --- | --- | --- | --- |
| **1** | **端侧手势识别与个性化自校准** | 固定死区 4°/满量程 30°/gamma 1.6 + 上电静态标定，换人重调 | 双头轻量模型 + 3s 自动自校准 + ≤ 30s 少样本个体适配 + OOD 拒识，全部在 MCU 上完成 | 跨人 ≥ 88%（受试者内 ≥ 95%）；首次可用 ≤ 3s；调参工时 ↓ ≥ 80%；推理 ≤ 15ms |
| **2** | **意图级共享自治** | 全手动，AI 不参与；环境判断全压给操作员 | 四级权限 + 置信度门限 + 一键接管 + 失效降级 + 安全包络硬限幅 + 逐帧可审计 | 碰撞 ↓ ≥ 50%；完成时间 ↓ ≥ 25%；路径偏离 ↓ ≥ 30%；接管 ≤ 200ms；AI 引发危险动作 0 次 |
| **3** | **仿真–实物闭环** | 实物试错，无仿真、无对照、无回归门禁 | MuJoCo 孪生 + 域随机化 + 系统辨识 + 回归测试门禁（指标不劣化才准上实物） | 轨迹 RMSE ≤ 10%；仿真/实物成功率差 ≤ 10pp；策略变更回归覆盖 100% |

> **为什么这三条算「硬」创新**：每条都有明确的**对比基线、技术手段、可测判据**三要素，且判据能被第三方用同一套赛道复现。相比「探索了一种新交互方式」「面向军事应用」这类无法证伪的软表述，这三条是能被评委追问、也能被答辩现场演示的。
>
> **边缘智能不列入创新点**：它是上述三条的使能条件（让模型能跑在端侧、让时延进得了 100ms），写成创新点反而会被质疑「只是工程优化」。

### 4.3 三级测试与验收方案

沿用申报书的三步走，但把每一步的判据写死：

| 级别 | 场景 | 测试内容 | 通过判据 |
| --- | --- | --- | --- |
| **一级：基础功能** | 平整空旷室内 | 连接稳定性、端到端时延、映射准确性、自校准成功率 | 丢包 < 1%；时延 P95 ≤ 100ms；映射方向 100% 正确；自校准 10/10 成功 |
| **二级：性能对比** | 标准室内障碍赛道（S 形 + 窄门 + 目标对位） | 3 个经验水平（无/业余/熟练）× 各 ≥ 2 人，共 ≥ 6 人；每人每条件 10 次 | §4.2 第 9–12 项达标；CV ≤ 10% |
| **三级：实战化模拟** | 室外 + 楼宇（低照度、遮挡、烟尘条件可人工构造） | 侦察任务：进入 → 识别目标 → 回传 → 撤出；记录成功率、时间、链路中断次数 | 任务成功率 ≥ 80%；链路中断 ≤ 1 次/任务；无危险动作 |

**消融实验（证明「AI 真的有用」的关键证据）**：三个开关——自校准（开/关）、视觉 veto（开/关）、意图映射（开/关），共 2³ = 8 组，每组 ≥ 20 次任务，报告 **均值 ± 标准差**，用配对 t 检验或 Wilcoxon（p < 0.05）。没有消融，就只能证明「系统能跑」，证明不了「AI 带来了什么」。

### 4.5 展望（大模型仅在此处出现，不写入必做内容）

以下方向**不属于本项目考核范围，不占预算、不设指标**，只作为 2028 年后的延伸：

### 5.2 已实现部分的关键取舍（为什么这么写）

| 技术点 | 做法 | 为什么 |
| --- | --- | --- |
| 姿态融合 | Mahony AHRS（PI 互补滤波） | 比 Kalman 简单、参数少，ESP32 上单帧 < 0.2ms |
| 传感器驱动 | ICM20689 直接读寄存器，`WHO_AM_I` + 三重回读校验 | 硬件问题在初始化阶段就暴露，不进入「玄学调参」 |
| 陀螺零偏 | 上电静态 1000 点取均值 | 消除 ±20°/s 量级零偏，不打掉完全没法用 |
| 信号滤波 | **只滤加速度（4 点滑动平均），不滤陀螺** | 陀螺滤波 = 相位滞后 = 手感变肉 |
| 映射曲线 | 死区 4° → 归一化 → `s^1.6` → 限幅 100 | 一个参数调「软硬」，比分段线性少 5 个参数（也正是 B0 的局限所在） |
| yaw 漂移 | **不用 yaw 做控制**，云台水平改用角速度积分成增量 | 六轴 IMU 的 yaw 必然漂移，用绝对角会越来越偏 |
| 低延迟 | 关自动应答/重发，丢帧不补发 | 重发 3 次 = 750ms，比丢一帧（20ms）糟糕得多 |
| 协议健壮性 | `#pragma pack(1)` + `static_assert(sizeof==14)` + CRC-8 + 帧头 + 序号 | 跨平台对齐是最隐蔽的坑；断言让「改坏了」在编译期暴露 |
| 调试友好 | 三级调试 + CSV 模式 + BENCH 降级 + LED 状态灯 | 没有车、没有射频也能验证大部分逻辑 |

## 7. 快速开始（复现 B0 基线）

### 7.0 你需要准备的

**硬件**（完整清单见 [hardware_list.md](docs/hardware_list.md)）：
ESP32 DevKit V1 ×1、**ICM20689 模块 ×1（必须带 I2C 引出，建议备 2 只）**、nRF24L01+ 模块 ×1、100µF 电解电容 ×1、棉质手套 ×1、面包板与杜邦线。

**软件**：
- [Arduino IDE](https://www.arduino.cc/en/software) 2.x
- ESP32 开发板包（工具 → 开发板 → 开发板管理器 → 搜索 `esp32` 安装）
- **RF24** 库（工具 → 管理库 → 搜索 `RF24` → 选作者 **TMRh20** 的版本）

> ICM20689 不需要任何库 —— 固件直接操作寄存器。

### 7.1 接线

照着 [wiring_diagram.md](docs/wiring_diagram.md) 的表格接。三句话版本：

| 引脚 | → ESP32 | | nRF24L01 | → ESP32 |
| --- | --- | --- | --- | --- |
| VCC | 3V3 | | VCC | 3V3（⚠️ 不是 5V） |
| GND | GND | | GND | GND |
| SCL/SCLK | GPIO22 | | CE | GPIO4 |
| SDA/MOSI | GPIO21 | | CSN | GPIO5 |
| SDO/AD0 | GND（地址 0x68） | | SCK / MOSI / MISO | GPIO18 / 23 / 19 |
| **CS** | **3V3（必须拉高）** | | | |

> ⚠️ ICM20689 的 **CS 必须接 3V3**：芯片用 CS 电平判断走 SPI 还是 I2C，CS 悬空会导致 I2C 完全无应答，现象和"模块坏了"一模一样。

**外加一步，别省**：在 nRF24L01 的 VCC 与 GND 之间焊一个 **100µF 电解电容**（长脚接 VCC），引脚尽量短。这一步能解决约 60% 的"发几包就复位"问题。

### 7.2 打开并上传

Arduino IDE 要求**文件夹名 == 主文件名**：

1. 新建一个名为 `IMU_Car` 的文件夹
2. 把 `code/arduino/IMU_Car/IMU_Car.ino` 复制进去，得到 `IMU_Car/IMU_Car.ino`
3. 用 Arduino IDE 打开它
4. 选择开发板 **ESP32 Dev Module**、选择正确端口
5. 点上传

> 上传失败停在 `Connecting...` 时按住板上的 **BOOT** 键不放，看到开始写入再松开。

### 7.3 上电与标定

**这一步决定了能不能用**：

1. 把手套**平放**在桌面上（手心朝下，模块朝上）
2. **保持完全静止**，再插 USB 上电
3. 等待约 3 秒，期间 LED 常亮
4. 看到串口打印 `RUN  frame=20ms` 说明标定完成

正确的开机会是这样：

```
=========================================
 IMU Gesture Car - Glove TX  v1.0.0
=========================================
OK   ICM20689 ready (id=0x98, gyro +-500dps, accel +-4g)
CAL  keep the glove STILL and LEVEL for ~2s ...
CAL  gyro_bias(dps) = +0.31 -1.24 +0.87  (n=1000)
CAL  level_ref = roll +0.42  pitch -0.18
OK   nRF24L01 ready (ch=76, 250kbps, addr=GLV01)
RUN  frame=20ms  mode=DRIVE
PKT  sizeof=14  head=0xA5
```

> 没有 nRF24L01 也能跑：会打印 `ERR nRF24L01 init failed` 并进入 **BENCH 模式**，姿态数据照常输出，可以先把传感器部分调好。

### 7.4 验证姿态

打开串口监视器（**波特率 115200**），倾斜手套，观察输出：

```
[  130] roll=   2.10 pitch=  11.85 | vx=  20 vy=   0 pan=   0 tilt=   0 | DRIVE  ARMED tx=OK   imu=OK
```

| 期望现象 | 说明 |
| --- | --- |
| 平放时 `roll≈0`、`pitch≈0` | 水平基准正确 |
| 手指下压 → `pitch` 变正、`vx` 变正 | 前后方向正确 |
| 手腕右倾 → `roll` 变正、`vy` 变正 | 左右方向正确 |
| 倾斜 10° 左右时 `vx` 约 10 | 映射曲线符合设计 |

**方向反了怎么办**：不要改算法，改文件开头的符号宏即可：

```cpp
#define VX_INVERT  (-1)   // 前后反了
#define VY_INVERT  (-1)   // 左右反了
```

### 7.5 操作说明

| 操作 | 效果 |
| --- | --- |
| 手心朝下平放 | 停车（进入死区） |
| 前倾 10°~30° | 前进，角度越大越快 |
| 左/右倾 | 左右平移 |
| 短按 **BOOT** 键 | 切换 **DRIVE（行进）/ GIMBAL（云台）** 模式 |
| 长按 **BOOT** 键 1.5 秒 | 重新取水平基准（换人佩戴时用；L0 阶段将被自动自校准取代） |
| 手超过 30° | 输出饱和在 100，不会失控 |

## 8. 通信协议

### 8.1 v1 下行包（14 字节，已实现）

手套端每 20ms 发一个定长包，完整定义见 [分层说明 §9.2](docs/IMU人体姿态控制小车%20分层说明及具体实施步骤.md)。

| 偏移 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0 | `head` | u8 | 固定 `0xA5` |
| 1 | `seq` | u8 | 帧序号，算丢包率 |
| 2 | `flags` | u8 | bit0 手势有效 / bit1 云台模式 / bit2 IMU 正常 / bit3 标定中 / bit4 上帧发送失败 |
| 3 | `vx` | i8 | 前后 -100~100 |
| 4 | `vy` | i8 | 左右 -100~100 |
| 5 | `tilt` | i8 | 云台俯仰 -100~100 |
| 6-7 | `panDelta` | i16 | 云台水平**增量**，0.1° |
| 8-9 | `roll10` | i16 | 相对水平基准的 roll，0.1° |
| 10-11 | `pitch10` | i16 | 相对水平基准的 pitch，0.1° |
| 12 | `dtMs` | u8 | 本帧周期，查帧率 |
| 13 | `crc` | u8 | 前 13 字节的 CRC-8（poly 0x07） |

**射频参数（两端必须一致）**：信道 `76`、速率 `250kbps`、地址 `GLV01`、CRC `16bit`、负载 `14` 字节、关闭自动应答。

### 8.2 v2 扩展（规划中，用于共享自治）

| 方向 | 新增字段 | 说明 |
| --- | --- | --- |
| 下行 +4B | `intent_id` / `conf` / `model_ver` / `infer_ms` | 旧 14B 保持原样，车端只解前 14B 仍可用 |
| 上行 8B | `head 0x5A` / `seq` / `flags`（视觉在线·避障生效·权限等级 2bit·接管请求）/ `dMin10`（0.1m）/ `conf` / `aiLatMs` / `crc` | 20Hz；`d_min` 是「约束」级权限的唯一依据 |

> v2 目前是**协议草案**，实现进度见 §3.9 学期二。**不要**在没有上行链路的情况下宣称实现了共享自治——「约束 / 委托」两级在物理上依赖回传。

## 9. 常见问题

| 现象 | 最可能的原因 | 去这里查 |
| --- | --- | --- |
| 串口没输出 | USB 线只能充电 / 端口选错 | [debug_faq §2.1](docs/debug_faq.md) |
| `ERR ICM20689 init failed` | 没供电 / SDA-SCL 接反 / **CS 没拉高** / AD0 悬空；看打印的 `WHO_AM_I` 值 | [debug_faq §3.1](docs/debug_faq.md) |
| 姿态一直漂 | 零偏没标定好 / 手抖了 | [debug_faq §4.1](docs/debug_faq.md) |
| 方向相反 | `IMU_MOUNT` 或 `*_INVERT` 选错 | [debug_faq §4.4](docs/debug_faq.md) |
| `ERR nRF24L01 init failed` | 没 100µF 电容 / 接了 5V | [debug_faq §5.1](docs/debug_faq.md) |
| 发几包就复位 | nRF 发射瞬间掉压 | [debug_faq §5.4](docs/debug_faq.md) |
| 车能动但很迟钝 | 死区/满量程/gamma 参数 | [debug_faq §6.2](docs/debug_faq.md) |
| 车端收不到包 | 两端信道/地址/速率不一致 | [debug_faq §8.1](docs/debug_faq.md) |

**通用第一招**：把 `DEBUG_LEVEL` 改成 **2**（每帧输出），先看清数据，再猜原因。
